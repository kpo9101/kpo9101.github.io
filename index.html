2026.08 ~ 2026.10 (3개월)

포트폴리오 GitHub 시연 영상 프로젝트 브로셔

시설 배치·군중 AI·경제를 관리하는 Unreal 기반 싱글 플레이 축제 경영 시뮬레이션

규모·역할

OBB·SAT 기반 임의 각도 회전 배치 엔진

문제
90도 단위 회전만 지원하고 배치 영역을 축정렬 사각형(AABB)으로만 판정해, 해변에 시설을 비스듬히 놓을 수 없고 45도 회전 시설끼리 겹침 오탐이 발생했습니다.
해결
OBB 기하 연산을 별도 모듈로 분리하고 AABB 1차 필터 → SAT 정밀 판정의 2단계로 구성, 회전값은 정수(0.01도 단위)로 바꾸고 90도 각도는 격자 정렬이 유지되도록 스냅 처리했습니다.
결과
기존·신규 판정 등가성 회귀 테스트와 45도 오탐 테스트를 추가해 테스트 기준 오탐 0건, 지원 회전을 4방향 → 임의 각도로 확대했습니다.

묶음 편집과 실행 취소 — 시설 상태와 비용을 함께 되돌리는 구조

문제
여러 시설로 만든 먹거리 거리 등을 하나씩 다시 배치해야 했고, 묶음 중 일부만 적용되거나 실행 취소 시 시설과 비용이 어긋날 위험이 있었습니다.
해결
상대 위치를 유지한 이동·회전·복사 명령을 만들고, 비용·구획 규칙을 '사전검사 → 임시적용 → 확정/복구' 인터페이스로 연결해 실패 시 역순 복구했습니다.
해결
실행 취소는 현재 가격이 아닌 작업 당시의 지불·환급 기록으로 되돌리고(최근 64개), 배치 설계도는 이력과 분리해 저장·재사용하게 했습니다.
결과
묶음 편집·실행 취소·설계도 저장 관련 자동화 테스트 174개 통과(실패 0)로 부분 적용·비용 불일치 시나리오를 검증했습니다.

존 접근점 자동 보정 WorldSubsystem

문제
최대 582cm 단차가 이어진 지형에서 NavMesh가 끊기고, 구역 모서리 한 점을 대표점으로 써서 걸어갈 수 있는 구역도 도달 불가로 오판정됐습니다.
해결
지형 수정 없이 게임·PIE 월드 전용 WorldSubsystem을 만들어, 접근점 없는 구역 내부를 격자 샘플링하고 ProjectPointToNavigation·GetPathLength로 경로가 있는 점을 주입했습니다.
결과
OnWorldBeginPlay 시점에 첫 AI 결정 전 보정을 끝내고 실패 구역은 좌표와 함께 리포트, 출구 도달 가능 구역 약 65% → 100%, 격자 정렬에 따른 결과 편차 14~16개 → 0개.

Win64 Shipping 패키징 안정화 및 자동 검증 파이프라인

문제
Shipping Cook 후 구역 좌표가 에디터와 달라지고, 카메라 시작 높이와 군중 입구 지면 처리에 오류가 생겼습니다.
해결
에디터 전용 부모에 붙어 Cook 중 변형된 런타임 구역 13개를 월드 좌표를 유지한 채 분리하고 부모 체인 검사를 추가, 주차장 메시는 삼각형 충돌로 바꿔 NavMesh를 재생성했습니다.
결과
빌드 전용 DDC와 배포 ZIP SHA-256 검사를 자동화해 Cook 전후 구역 좌표 오차 0, 프로젝트 전체 자동화 테스트 1,148개 통과, 배포 파일 100개 해시 전수 일치.

EOS 기반 3인칭 협동 보스 레이드 액션 RPG의 멀티플레이 세션·레이드 결과 시스템 개발

규모
5인 프로젝트
담당
EOS 멀티플레이 세션 설계, 방 생성·이름 중복 검증, 레이드 MVP 선정 알고리즘, 스코어보드 복제 구조, 자동화 테스트 작성
기술
Unreal Engine 5.7, C++, GAS, EOS, Online Subsystem, Slate, PowerShell

역할 편향 없는 레이드 MVP 선정 산식

문제
누적 피해량만으로 MVP를 뽑아, 피해와 회복의 단위·규모 차이 때문에 힐러가 구조적으로 선정될 수 없었습니다.
해결
산식을 PlayerState와 분리된 순수 함수로 만들고, 역할별 최댓값 기준 0~1 정규화 후 주 기여 0.8·보조 0.2로 가중합, 동점은 사망 수 → 주 기여 → PlayerId 순으로 안정 정렬했습니다.
결과
Formula·RoleFairness·ZeroContribution·InvalidStats·TieBreaks 자동화 테스트 5종으로 역할 공정성, 결과 결정성, NaN·음수 입력 방어를 검증했습니다.

오버킬·오버힐을 걸러낸 스코어보드 집계

문제
GAS가 HP 적용 전 수치를 그대로 통계에 반영해, 보스 오버킬과 파티원 오버힐이 실제 HP 변화보다 크게 집계됐습니다.
해결
PreGameplayEffectExecute에서 적용 전 수치를 0~MaxHealth로 제한해 실제 변화량을 구하고, 서버 권한·전투 중·0이 아닌 변화만 집계해 중복과 자기 회복을 제외했습니다.
결과
피해·회복 통계와 이벤트 브로드캐스트를 실제 HP 변화량 기준으로 통일해 과대 집계를 제거했습니다.

EOS 세션 방 이름 검증·중복 방지

문제
방장 닉네임으로만 방을 구분해 같은 닉네임의 방을 구별할 수 없고, 방 이름을 지정할 수도 없었습니다.
해결
방 이름 정규화(공백 제거, 한글·영문·숫자 2~24자)와 세션 속성 광고를 추가하고, 생성 전 같은 이름을 먼저 조회하는 2단계 플로우를 구현했습니다.
결과
같은 이름의 방 생성을 사전 조회로 차단하고 레이드 중에도 이름 점유를 유지했으며, 방 이름 검증 자동화 테스트를 추가했습니다.
